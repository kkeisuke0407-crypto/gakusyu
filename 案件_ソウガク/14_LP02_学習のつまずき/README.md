## 流れ（v3）
悩み → 公式の体験談 → 変化 → 意味づけ → 次の疑問、をくり返してソウガクまで運ぶ。

1. FV：タイトル → PR帯 → アイキャッチ（`01_fv_evening-desk`）→ 悩み → `mt-summary`「このあと見ていく、3つの実例」→ ボタン（`#sogaku` へページ内ジャンプ）
2. `mt-talk`：読者の迷いを自分事に（保護者×編集部、4つの吹き出し。サービス名は出さない）
3. 実例A 集中が切れる子（小学5年生）：H2 → 扉画像 → `mt-say → mt-story → mt-review` → 意味づけ → 次の疑問
4. 実例B 計算につまずく子（小学2年生）：同じ形
5. 実例C 家で教えるとケンカになる家庭（小学4年生）：同じ形 → `mt-oneline`「親が先生役を続けなくてもいい。」→ `07_after_lesson_share` → `mt-voice` で3つの共通点
6. `mt-bridge`「＼ソウガク／」で画面を切り替え → 公式KV
7. 「なぜ、その子ごとに学び方を変えられるの？」：扉＝公式の指導コミュニケーションツール画面 → `mt-spec`（中に最初のASPボタン `#cta-sogaku`）
8. 「でも、オンラインで座っていられる？」：4つ目の実例（中学2年生）で反論を処理 → テキストリンク（LP01と同じ行）
9. ここから下はLP01をそのまま流用：無料体験（返金保証）／料金／FAQ／最終CTA／注記／運営者情報／フッター／追従ボタン（起点だけ `#cta-sogaku`）

## パーツのルールに合わせたところ（v2からの変更）
| v2 | v3 |
|---|---|
| `mt-conclusion` を4回（ルール：比較表のすぐ下だけ） | 使わない。意味づけは本文＋`mt-mark`（1セクション2か所まで） |
| `mt-review` の本文が編集部の解説 | 本文＝公式サイト掲載の声の**原文の抜粋**、見出し＝属性（学年・保護者）。下に出典の注記 |
| `mt-talk` の編集部アイコンが文字、吹き出しが3〜5行 | アイコンはLP01と同じ画像（`icon_editor.webp`）、吹き出しは全部2行以内 |
| `mt-summary` の項目が2行 | 1項目1行 |
| `mt-bridge` が「ソウガクです。」 | ＼ソウガク／（ページに1回） |
| H2直下に画像がないセクション（実例Bは画像なし） | 全H2の直下に扉画像（実例Aは14、Bは05、Cは12、仕組みは公式ツール画面、反論は13） |
| 文章だけの区間が最大約1,750px | 375px幅で最大約1,190px（1.5画面以内） |
| 仕組みの説明（h3×3）のあとにボタン | `mt-spec` の中にボタン（パーツの形）。h3×3の中身は `mt-spec` の項目に集約 |
| 反論の実例のあと `#trial` へのボタン（すぐ下のセクションへのジャンプ） | LP01と同じテキストリンク（公式サイトの無料体験へ） |
| `mt-say` が3〜4行 | 2行以内 |
